# قرار تقني: ترويسات HTTP في مشغل Windows

## الحالة التي تم التحقق منها

المشروع يستهدف `net8.0-windows` ويستخدم:
- `LibVLCSharp.WPF 3.10.2`
- `VideoLAN.LibVLC.Windows 3.0.24`

في `windows/VlcPlaybackPrototype.xaml.cs` تُضاف حاليًا خيارات الوسيط:
- `:http-user-agent=...`
- `:http-referrer=...`

توثيق LibVLCSharp يوضح أن `Media.AddOption` يمرر خيارات LibVLC، لكن أسماء الخيارات وتوفرها تختلف باختلاف إصدار LibVLC والبناء. وثائق واجهة LibVLC لا تعد بواجهة عامة لتمرير مجموعة اعتباطية من ترويسات HTTP لكل طلب.

المراجع:
- LibVLCSharp Media.AddOption: https://docs.videolan.me/libvlcsharp/api/LibVLCSharp.Shared.Media.html
- إرشادات خيارات LibVLC: https://docs.videolan.me/libvlcsharp/docs/how_do_I_do_X.html
- LibVLC media API: https://videolan.videolan.me/vlc/master/group__libvlc__media.html

## القرار

لا نضيف خيارات مخمّنة مثل `:http-header=Origin:...` أو `:http-cookie=...` قبل إثبات وجودها في إصدار LibVLC 3.0.24 المضمّن واختبارها. الواجهة العامة الموثقة في LibVLCSharp لا تثبت أن هذه الخيارات مدعومة، ولا تثبت أنها ستُطبق على كل طلبات HLS الفرعية (playlist/segments/keys).

يستمر التطبيق حاليًا في تمرير User-Agent وReferer فقط. يجب ألا يعلن المستقبل دعم Origin أو Cookie أو Accept أو Accept-Language حتى يُختبر ذلك فعليًا.

## مسار التنفيذ المقترح

إذا أثبت اختبار تكامل أن روابط Cast تحتاج ترويسات إضافية، فالخيار القابل للتحكم هو طبقة HTTP وسيطة محلية داخل تطبيق Windows:
1. تستقبل عنوان المصدر والترويسات بعد التحقق من JSON.
2. تجلب المصدر مع الترويسات المطلوبة مع احترام HTTPS والتحويلات ونطاقات المضيف المسموح بها.
3. تمرر Range وطلبات المحتوى الجزئي لملفات MP4.
4. تعيد كتابة روابط قوائم HLS الفرعية (playlists/segments/keys) إلى مسارات الوسيط كي لا تضيع الترويسات في الطلبات التابعة.
5. تمنع الوصول إلى loopback والشبكات الخاصة غير المقصودة وأي وجهات داخلية حساسة، وتضع حدودًا للحجم والمهلة وعدد الاتصالات.
6. تُغلق موارد الوسيط عند إيقاف الوسائط أو استبدالها.

هذا تصميم مقترح وليس تنفيذًا موجودًا. لا ينبغي بناء Proxy ساذج يعيد تمرير أي URL يرسله عميل الشبكة؛ ذلك قد يفتح ثغرة SSRF. كما أن إضافة Origin وحدها ليست ضمانًا لقبول الخادم المصدر.

## بوابة الاختبار قبل التنفيذ

- اختبار MP4 يتطلب Range وContent-Range و206.
- اختبار HLS يتطلب قائمة رئيسية، قائمة فرعية، مقاطع، ومفاتيح مشفرة إن وجدت.
- التحقق من وصول الترويسات إلى كل طلب تابع، لا إلى طلب الملف الأول فقط.
- اختبار الإيقاف والاستبدال السريع لمنع استمرار اتصالات قديمة.

حتى اكتمال هذه الاختبارات، تظل مطابقة Headers جزئية ولا يُعلن توافق كامل مع روابط Google Video.
