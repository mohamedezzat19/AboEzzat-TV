# أبو عزت TV | AboEzzat Receiver for Windows

الهدف هو نقل تجربة وإمكانيات **AboEzzat Receiver Android** إلى Windows، ثم بناء تطبيقات مستقلة لـ LG webOS وSamsung Tizen، مع إبقاء مستودعي Android Receiver وAboEzzat Cast الأصليين دون تعديل.

## الحالة الحالية — 10 نوفمبر 2026

يوجد فرع Windows النشط:
`feature/libvlc-header-playback`

تم إنشاء تطبيق Windows باستخدام **WPF و.NET 8 وLibVLC**. أحدث نسخة من الفرع نجحت في GitHub Actions في بناء حزمة Windows x64 ذاتية التشغيل وإنشاء المثبّت `AboEzzat-TV-Setup.exe`:

https://github.com/mohamedezzat19/AboEzzat-TV/actions/runs/42786013548

آخر تحسينين في هذا البناء:
- ترتيب طلبات Cast في طابور واحد حتى لا يتغلب طلب قديم متأخر على فيديو أحدث.
- إرسال رد HTTP إلى Cast فور قبول الطلب، قبل فحص CDN الاختياري، وتجنب فحص روابط الفيديو المعروفة باعتبارها صورًا.

نجاح GitHub Actions يؤكد **التجميع والنشر وإنشاء ملف التثبيت ورفعه كـ Artifact فقط**. لم يتم إثبات التثبيت والتشغيل على جهاز Windows حقيقي أو نجاح استقبال وتشغيل وسائط مرسلة من AboEzzat Cast.

## الموجود في كود Windows الحالي

- واجهة WPF عربية بملء الشاشة مع عناصر تحكم للفيديو.
- خادم TCP/HTTP على المنفذ 8081 لاستقبال `POST /play` وروابط query.
- إعلان اكتشاف UDP multicast على `239.255.42.99:37020`.
- استقبال رابط فيديو ورابط صوت منفصل وتشغيلهما عبر LibVLC.
- استقبال الصور وقائمة صور وعرض شرائح بفواصل زمنية.
- سجل تشغيل ومواضع استكمال مشاهدة محفوظة محليًا.
- زر بحث يدوي عن ترجمة عربية.
- رد `ping/status`؛ ويعيد `status` حالة الاستقبال.

هذه قدرات موجودة في الشيفرة وليست كلها مختبرة عمليًا بعد.

## فجوات معروفة قبل إعلان التوافق

- أوامر الريموت التي يدعمها Android Receiver مثل `stop` و`play_pause` و`rw` و`ff` و`previous` و`next` و`volume_up` و`volume_down` و`mute` لم تُنفذ بعد في مستقبل Windows؛ حاليًا يتعرف Windows على `ping/status` فقط كأوامر مستقلة.
- تمرير Headers إلى LibVLC محدود حاليًا بـ User-Agent وReferer؛ دعم Cookie وباقي الترويسات يحتاج استكمالًا واختبارًا.
- التزامن بين مسار الفيديو ومسار الصوت المنفصل موجود في الكود، لكنه يحتاج اختبارًا على ملفات وروابط حقيقية.
- فحص نوع بعض روابط CDN غير ذات الامتداد قد يستخدم طلب HEAD اختياريًا؛ ترتيب الطلبات يمنع تبديل الوسائط بترتيب خاطئ، لكن يجب قياس أثر ذلك على سرعة الطلبات المتتابعة.
- لا توجد بعد اختبارات تكامل آلية تثبت اتصال AboEzzat Cast بالتطبيق.

## التثبيت والاختبار المطلوبان

1. افتح تشغيل GitHub Actions أعلاه ونزّل Artifact باسم `AboEzzat-TV-Windows-Setup`.
2. فك ضغطه وشغّل `AboEzzat-TV-Setup.exe` على Windows x64.
3. وافق على إضافة قاعدة جدار الحماية للشبكة الخاصة، ولا تفتح المنفذ على الإنترنت العام.
4. وصّل الكمبيوتر والهاتف على الشبكة المحلية نفسها.
5. اختبر ظهور AboEzzat TV داخل AboEzzat Cast، ثم أرسل صورة، وفيديو MP4، ورابط HLS، وفيديو بصوت منفصل، ورابطًا يحتاج Headers.
6. اختبر أوامر الريموت بعد تنفيذها، وسجّل أي فشل مع نوع الرابط ورسالة الخطأ.

## الفروع والمنصات

- `feature/libvlc-header-playback`: تطبيق Windows WPF الحالي.
- `main`: يحتوي نموذج Electron الأقدم، وليس نفس نسخة Windows WPF الحالية.
- LG webOS وSamsung Tizen: لم تُبنَ لهما تطبيقات بعد؛ يحتاج كل نظام تطبيقًا وحل استقبال/اكتشاف متوافقًا مع قيودهما. لا يُعد مثبت Windows تطبيقًا صالحًا للتثبيت على التلفزيون.

## الحفاظ على التطبيقات الأصلية

لن يتم تعديل مستودع AboEzzat Receiver Android أو AboEzzat Cast ضمن هذا المشروع دون موافقة منفصلة.
