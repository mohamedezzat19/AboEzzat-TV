# أبو عزت TV | AboEzzat Receiver for Windows

الهدف هو نقل تجربة وإمكانيات **AboEzzat Receiver Android** إلى Windows، مع إبقاء مستودعي Android Receiver وAboEzzat Cast الأصليين دون تعديل.

## الحالة الحالية — 9 نوفمبر 2026

يوجد فرع Windows النشط:
`feature/libvlc-header-playback`

تم إنشاء تطبيق Windows باستخدام **WPF و.NET 8 وLibVLC**، ونجح GitHub Actions في بناء حزمة Windows x64 وإنشاء ملف التثبيت `AboEzzat-TV-Setup.exe` في التشغيل التالي:

https://github.com/mohamedezzat19/AboEzzat-TV/actions/runs/42623047162

نجاح البناء يؤكد نجاح التجميع والنشر وإنشاء ملف التثبيت فقط. **لم يتم بعد تأكيد التثبيت والتشغيل على جهاز Windows حقيقي أو اختبار إرسال فعلي من AboEzzat Cast**.

## الموجود في كود Windows الحالي

- واجهة WPF عربية بملء الشاشة مع عناصر تحكم للفيديو.
- خادم TCP/HTTP على المنفذ 8081 لاستقبال طلبات `POST /play` وروابط query.
- إعلان اكتشاف UDP multicast على `239.255.42.99:37020`.
- تشغيل الفيديو والصوت عبر LibVLC، مع دعم مسار صوت منفصل.
- استقبال الصور وقائمة صور وعرض شرائح بفواصل زمنية.
- سجل تشغيل ومواضع استكمال مشاهدة محفوظة محليًا.
- زر بحث يدوي عن ترجمة عربية.

هذه قدرات موجودة في الشيفرة، وليست كلها مختبرة عمليًا بعد. تمرير ترويسات الوسائط إلى VLC محدود حاليًا بـ User-Agent وReferer، ويحتاج اختبارًا وتوسعة قبل ضمان روابط تتطلب Cookie أو ترويسات أخرى.

## التثبيت والاختبار المطلوبان

1. تنزيل artifact `AboEzzat-TV-Windows-Setup` من تشغيل GitHub Actions المرتبط أعلاه.
2. تثبيت البرنامج على Windows x64 وتشغيله.
3. توصيل الكمبيوتر والهاتف/التلفزيون على الشبكة المحلية نفسها.
4. اختبار ظهور AboEzzat TV داخل AboEzzat Cast، ثم إرسال صورة ورابط MP4 ورابط HLS ورابط يحتاج Headers.
5. تسجيل أي فشل مع نوع الرابط ورسالة الخطأ قبل إعلان التوافق.

## الفروع والمنصات

- فرع `feature/libvlc-header-playback`: تطبيق Windows WPF الحالي.
- فرع `main`: يحتوي نموذج Electron الأقدم، وليس نفس نسخة Windows WPF الحالية.
- LG webOS وSamsung Tizen: لم تُبنَ لهما تطبيقات بعد؛ يحتاج كل نظام تطبيقًا وحل استقبال/اكتشاف متوافقًا مع قيوده.
