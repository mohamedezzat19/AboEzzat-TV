# أبو عزت TV | AboEzzat Receiver for Windows

الهدف هو نقل تجربة وإمكانيات **AboEzzat Receiver Android** إلى Windows، ثم بناء تطبيقات مستقلة لـ LG webOS وSamsung Tizen، مع إبقاء مستودعي Android Receiver وAboEzzat Cast الأصليين دون تعديل.

## الحالة الحالية — 14 نوفمبر 2026

يوجد فرع Windows النشط:
`feature/libvlc-header-playback`

تم إنشاء تطبيق Windows باستخدام **WPF و.NET 8 وLibVLC**. أحدث بناء مكتمل بنجاح هو تشغيل GitHub Actions رقم **43395414174** على commit `676804e4a8080676834dea278f0516a0b6e7bd1a`:

https://github.com/mohamedezzat19/AboEzzat-TV/actions/runs/43395414174

نجحت جميع خطوات البناء: Restore وPublish self-contained Windows x64 وإنشاء `AboEzzat-TV-Setup.exe` ورفع Artifact باسم `AboEzzat-TV-Windows-Setup`. حجم الـArtifact المضغوط في GitHub هو 131,001,948 بايت. بعد تنزيله وفك ضغطه، كان حجم ملف المثبّت 131,515,387 بايت، وبصمة SHA-256 للملف التنفيذي:

`ed83d10152f0caa282bdb5ce0dc22ae749430b644ac993456b793182860d9005`

يوجد تعديل أحدث على معالجة طلبات الوسائط في commit `701506fef91ddb701e410065de1633cfd7032571`: نقل فحص HEAD الاختياري لتحديد الصور البعيدة خارج مسار استقبال HTTP، بعد إرسال تأكيد الاستلام إلى Cast. كما أُضيف بعده حجز HTTP.sys للمستخدمين العاديين في المثبّت، وصُحّح تعليق الكود الذي كان يصف المستمع خطأً بأنه TcpListener. هذه التعديلات الأحدث لم تدخل بعد في Artifact البناء المؤكد رقم 43395414174.

## الموجود في كود Windows الحالي

- واجهة WPF عربية بملء الشاشة مع عناصر تحكم للفيديو.
- خادم TCP/HTTP مخصص يستمع على كل واجهات IPv4 المحلية على المنفذ 8081، ويستقبل `POST /play` وروابط query.
- قاعدة جدار حماية Windows للاتصالات الواردة على TCP 8081 ضمن ملف تعريف Private.
- إعلان اكتشاف UDP multicast على `239.255.42.99:37020`.
- استقبال رابط فيديو ورابط صوت منفصل وتشغيلهما عبر LibVLC.
- استقبال الصور وقائمة صور وعرض شرائح بفواصل زمنية.
- سجل تشغيل ومواضع استكمال مشاهدة محفوظة محليًا.
- زر بحث يدوي عن ترجمة عربية.
- أوامر الريموت المطابقة لـ AboEzzat Cast: `stop` و`play_pause` و`rw` و`ff` و`prev` و`next` و`volume_up` و`volume_down` و`mute` (ويقبل المستقبل أيضًا الاسم البديل `previous`).

هذه قدرات موجودة في الشيفرة وليست كلها مختبرة عمليًا بعد.

## توافق بروتوكول AboEzzat Cast — ما تمت مراجعته

تمت مراجعة مسارات الإرسال في مستودع AboEzzat Cast:
- `POST /play` مع JSON يحتوي `url` و/أو `audio`.
- `GET /?url=...` لإرسال رابط مباشر.
- `GET /?command=ping` للتحقق من اتصال المستقبل.
- أوامر الريموت تُرسل كـ `GET /?command=...`.
- البحث اليدوي عن المستقبل في Cast يحاول فتح اتصال TCP على المنفذ 8081.

كود Windows الحالي يحتوي مقابلات لهذه المسارات والأوامر. هذه مراجعة ساكنة للكود وليست اختبار تكامل بين جهازين.

## إعداد الاستماع والشبكة

يستخدم التطبيق `HttpListener` فوق Windows HTTP.sys على العنوان `http://+:8081/`. لذلك يحتاج حجز URLACL قبل تشغيله كمستخدم عادي. المثبّت يضيف الآن الحجز `http://+:8081/` لمجموعة `BUILTIN\\Users`، ويزيله عند إلغاء التثبيت، بالإضافة إلى قاعدة جدار الحماية الخاصة لـ TCP 8081. إذا تعذر بدء الخدمة، تحقق أن الحجز لم يتعارض مع تطبيق آخر وأن المنفذ 8081 غير مستخدم وأن الشبكة مصنفة Private.

لا تفتح المنفذ على الإنترنت العام؛ الاستخدام المقصود هو شبكة LAN موثوقة.

## فجوات معروفة قبل إعلان التوافق

- تمرير Headers إلى LibVLC محدود حاليًا بـ User-Agent وReferer؛ دعم Cookie وباقي الترويسات يحتاج استكمالًا واختبارًا.
- التزامن بين مسار الفيديو ومسار الصوت المنفصل موجود في الكود، لكنه يحتاج اختبارًا على ملفات وروابط حقيقية.
- فحص نوع بعض روابط CDN غير ذات الامتداد يستخدم طلب HEAD اختياريًا في مهمة منفصلة؛ التعديل الأحدث يزيل الفحص المكرر من طابور HTTP، ويحتاج اختبار إرسال طلبات Cast متتابعة بسرعة.
- صورة الترحيب الأصلية من Android لم تُضمّن بعد في مجلد Windows، كما أن اختصاري المتصفح والإعدادات غير مكتملين في الواجهة الحالية.
- لا توجد بعد اختبارات تكامل آلية تثبت اتصال AboEzzat Cast بالتطبيق.
- لم يتم اختبار MP4 أو HLS أو الصوت المنفصل أو الصور أو أوامر الريموت على جهاز Windows فعلي حتى الآن.

## التثبيت والاختبار المطلوبان

1. آخر مثبت مؤكد البناء هو Artifact من تشغيل GitHub Actions رقم 43395414174. نزّل Artifact باسم `AboEzzat-TV-Windows-Setup` من صفحة التشغيل.
2. التعديلات بعد commit `676804e4a8080676834dea278f0516a0b6e7bd1a`، بما فيها commit `701506fef91ddb701e410065de1633cfd7032571` وتحديث URLACL، تحتاج بناءً جديدًا؛ لا تستخدم Artifact القديم للتحقق من إصلاحات الشبكة الأخيرة.
3. فك ضغط الـArtifact وشغّل `AboEzzat-TV-Setup.exe` على Windows x64.
4. وافق على قاعدة جدار الحماية للشبكة الخاصة، ولا تفتح المنفذ على الإنترنت العام.
5. وصّل الكمبيوتر والهاتف على الشبكة المحلية نفسها.
6. اختبر ظهور AboEzzat TV داخل AboEzzat Cast، ثم أرسل صورة، وفيديو MP4، ورابط HLS، وفيديو بصوت منفصل، ورابطًا يحتاج Headers.
7. اختبر أوامر الريموت، وسجّل أي فشل مع نوع الرابط ورسالة الخطأ.

## الفروع والمنصات

- `feature/libvlc-header-playback`: تطبيق Windows WPF الحالي.
- `main`: يحتوي نموذج Electron الأقدم، وليس نفس نسخة Windows WPF الحالية.
- LG webOS وSamsung Tizen: لم تُبنَ لهما تطبيقات بعد؛ يحتاج كل نظام تطبيقًا وحل استقبال/اكتشاف متوافقًا مع قيودهما. لا يُعد مثبت Windows تطبيقًا صالحًا للتثبيت على التلفزيون.
